# CVM Protocol

The Spryte CVM (Context Vending Machine) exposes an MCP tool over Nostr relays. This page covers the protocol details for direct integration without the client library.

## MCP Tool: `generate-spryte`

### Input Schema

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `pubkey` | `string` | Yes | 64-character hex Nostr pubkey |
| `cellSize` | `number` | No | 32–512 pixels, default 128 |
| `uploadServer` | `string` | No | Blossom server URL (uses server default if omitted) |

### Output

```json
{
  "spriteUrl": "https://blossom.example/abc123.png",
  "mappingUrl": "https://blossom.example/def456.json",
  "pubkeyCount": 342,
  "cellSize": 128
}
```

## Nostr Event Kinds

Communication happens over Nostr using these event kinds:

| Kind | Direction | Description |
|------|-----------|-------------|
| **25910** | Client → CVM | MCP tool call request (encrypted) |
| **11316** | CVM → Client | MCP tool call response |
| **11317** | CVM → Client | Progress notifications |
| **11318** | CVM → Client | Payment required notification (CEP-8) |
| **11319** | Client → CVM | Payment confirmation |
| **11320** | CVM → Client | Payment acknowledged |

All events are encrypted between client and server using NIP-44.

## NostrClientTransport Setup

To call the CVM directly without the `@spryte/client` wrapper, use the `@contextvm/sdk` transport:

```typescript
import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import {
  NostrClientTransport,
  PrivateKeySigner,
  ApplesauceRelayPool,
} from "@contextvm/sdk";

const signer = new PrivateKeySigner("your-hex-private-key");
const relayPool = new ApplesauceRelayPool(["wss://relay.damus.io"]);

const transport = new NostrClientTransport({
  signer,
  relayHandler: relayPool,
  serverPubkey: "spryte-cvm-hex-pubkey",
  isStateless: true,
});

const client = new Client({
  name: "my-app",
  version: "1.0.0",
});

await client.connect(transport);
```

## Direct MCP Calls

Once connected, call the tool directly:

```typescript
const result = await client.callTool({
  name: "generate-spryte",
  arguments: {
    pubkey: "target-hex-pubkey",
    cellSize: 128,
  },
});

// Parse the response
const content = result.content as Array<{ type: string; text: string }>;
const textContent = content.find((c) => c.type === "text");
const output = JSON.parse(textContent.text);

console.log(output.spriteUrl);
console.log(output.mappingUrl);
```

Or use `structuredContent` if the server provides it:

```typescript
if (result.structuredContent) {
  const output = result.structuredContent;
  console.log(output.spriteUrl);
}
```

## Payment Flow

When the CVM requires payment (CEP-8):

1. Client sends `tools/call` request
2. CVM responds with `notifications/payment_required` containing a BOLT11 invoice
3. Client pays the invoice (manually or via NWC)
4. Client sends payment confirmation
5. CVM processes the request and returns the result

### Automatic Payment (NWC)

The `@contextvm/sdk` includes a payment handler that auto-pays via NWC:

```typescript
import {
  withClientPayments,
  LnBolt11NwcPaymentHandler,
} from "@contextvm/sdk";

// Wrap the transport with payment handling
const paidTransport = withClientPayments(transport, {
  paymentHandler: new LnBolt11NwcPaymentHandler("nostr+walletconnect://..."),
});

const client = new Client({ name: "my-app", version: "1.0.0" });
await client.connect(paidTransport);
```

### Manual Payment

Without NWC, the client receives a `notifications/payment_required` notification. Extract the BOLT11 invoice, pay it externally, and confirm:

```typescript
// Listen for payment notifications on the transport
// The exact handling depends on your MCP client setup
```

## ctxcn Code Generation

The `SpryteCvmClient` in `@spryte/client` is generated by [`@contextvm/ctxcn`](https://www.npmjs.com/package/@contextvm/ctxcn), which reads the CVM's tool definitions and produces a type-safe TypeScript client:

```bash
# Generate client from a running CVM
npx ctxcn add <cvm-pubkey>

# Update when the CVM's tools change
npx ctxcn update
```

This produces typed methods matching each MCP tool, handling serialization and response parsing automatically.
